# Glossary MCP Server

The Glossary server answers what a Veoveo hosting term means. It is the Rust server
template, so its domain stays small and its structure is the part to copy.

## Standards And Protocols

| Standard or protocol | Implemented profile |
|---|---|
| [Model Context Protocol](https://modelcontextprotocol.io/specification/) | Protocol version `2026-07-28`; JSON-RPC 2.0 over stateless Streamable HTTP with one tool, resources and templates, one prompt, completion and structured content. |
| [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/) | Tool input and output schemas generated by Schemars. |
| RFC 3986 / RFC 6570 | Concrete `glossary://` URIs and the level 1 template `glossary://term/{term_id}`. |
| Veoveo MCP server contract | Revision 4, hosted through `veoveo_mcp_contract::hosting`. |

## Surface

| Surface | Name | Behavior |
|---|---|---|
| Tool | `define` | Returns one `Definition` as structured content. An unknown term is a resource-not-found error. |
| Resource | `glossary://terms` | Every term with its title and URI, as JSON. |
| Template | `glossary://term/{term_id}` | One `Definition`, as JSON. `term_id` completes from the glossary. |
| Prompt | `explain_term` | Asks the model to read one term resource and explain it. |
| Well-known | `glossary://docs`, `glossary://docs/{doc_id}`, `glossary://contract` | Served by the shared host from the embedded crate documents. |

`DefineRequest` rejects undeclared fields. The generated input schema closes the
object, and the hosted gateway test checks that an extra argument produces a completed
tool result with `isError: true` before the domain handler runs.

## Module Layout

The library exposes the public contract to clients, tests and tools. Its features
layer the crate so a consumer builds only what it uses:

| Feature | Adds | Dependencies |
|---|---|---|
| `contract` | `contract` module | `schemars`, `serde`, `veoveo-types` |
| `runtime` | `glossary` module | none beyond `contract` |
| `mcp` (default) | the `glossary-mcp` binary | rmcp, tokio, clap and `veoveo-mcp-contract` |

```text
src/
  lib.rs                 feature-gated library modules
  contract.rs            TermId, GlossaryResource and the tool shapes
  glossary.rs            domain data and lookup, without MCP types
  bin/server.rs          configuration and the HostedServer builder
  bin/server/setup.rs    GlossaryContract: identity, capabilities and discovery
  bin/server/handler.rs  GlossaryMcp: tools, reads, prompts and completion
  bin/server/tests.rs    in-process gateway tests
```

## Reads And Caching

`GlossaryMcp::read` receives a parsed `GlossaryResource`. Term and index reads return
`DomainRead::private`, which a client may reuse for one second. The glossary is fixed
at build time, so no read needs `DomainRead::no_store`.
