# Store Write Cost Before Feed Adoption

The controlled workload compares three transaction shapes before phase 5 changes
production writers. Source base `5dbcc4a5` still uses the shared sequence and event
rows. The measurement harness and its schema bootstrap are added with this record.

Each operation updates one writer-owned domain row. `shared_sequence` also inserts
an event with the current event schema's four indexes, original-value change feed,
and a sequence defined with `BATCH 1`. `independent_event` inserts the same event
with a preassigned unique sequence, isolating sequence allocation from other event
costs. `changefeed_only` writes only the domain row with its native change feed.
The independently assigned values are an experimental control, not a proposed
ordering contract.

## Environment And Method

The native fixture runs the qualified SurrealDB 3.3.0 RocksDB image on this developer
host's Ryzen 9 5950X and NVMe filesystem. Docker limits the fixture to two CPUs and
2 GiB RAM, with a 64 MiB block cache and two 16 MiB write buffers. The cluster and
BuildKit are stopped. Chrome stays open with no running installation workload.

Each profile uses a fresh fixture and the complete platform schema. Schema setup
runs as the isolated fixture admin; measured operations use database-editor
credentials. One or eight concurrent Tokio writers share one multiplexed WebSocket
client. Each writer performs 64 transactions. Three rounds rotate profile order.
Setup and cleanup are outside the timed region. Samples include the first write;
there is no discarded warmup or selected best run.

The harness checks every final domain revision and event count. It retries only a
database-reported transaction conflict, with a limit of 128 attempts and 100–1600 µs
backoff. A ten-minute timeout covers the complete experiment, and the fixture owns
all container cleanup. All 5,184 operations committed; all 18 fixtures were removed.

Run with the repository's qualified native environment:

```sh
cargo test -p veoveo-platform-store --test write_cost -- \
  --ignored --exact compare_shared_sequence_and_native_feed_writes --nocapture
```

## Results

Elapsed time is the median of three runs. Operation percentiles pool all samples
for that profile and writer count. Times include the client round trip and commit
acknowledgement, not only the database's internal commit step.

| Writers | Profile | Run elapsed ms | Operation p50 ms | Operation p95 ms | Client conflicts/retries |
|---:|---|---:|---:|---:|---:|
| 1 | Shared sequence | 177.261 | 2.108 | 2.906 | 0 |
| 1 | Independent event | 73.751 | 1.008 | 1.802 | 0 |
| 1 | Native feed only | 100.521 | 1.095 | 1.474 | 0 |
| 8 | Shared sequence | 999.344 | 13.072 | 43.151 | 0 |
| 8 | Independent event | 314.987 | 3.299 | 8.124 | 0 |
| 8 | Native feed only | 242.954 | 2.636 | 6.907 | 0 |

At eight writers, removing shared sequence allocation reduces median elapsed time
by 68.5% in this workload. Removing the extra event row and indexes reduces it by a
further 22.9%. Native-feed-only writes produce one domain row mutation per operation;
the event profiles produce two row mutations and maintain four extra indexes.
These are logical write counts, not measured physical disk amplification.

No transaction conflict reached the client, so the harness performed no retries.
The experiment does not expose the database's internal retry count and cannot
attribute latency to transaction conflicts. Sequential independent-event and
native-feed results overlap enough that they do not establish a single-writer
benefit from removing the event row.

This synthetic workload isolates transaction shape. It does not establish installed
throughput, multiple-connection behavior, or the latency of any complete MCP request.
Repeat the comparison after the consumer/writer cut and qualify reactive recovery
separately. [Per-run metrics](native-before-2026-10-01.csv) and
[all attempt and operation samples](native-before-2026-10-01.jsonl) preserve the
measurements used here. The [owning harness](../tests/write_cost.rs) defines the
queries, concurrency and checks.
