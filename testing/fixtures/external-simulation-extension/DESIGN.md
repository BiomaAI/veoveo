# Anonymous Simulation Extension Design

This fixture proves that an independently owned Python MCP server can package a
simulator-hosted live-view contract without a platform renderer or source-tree import.
It is a protocol fixture rather than visual or GPU evidence.

## Standards And Protocols

| Standard or protocol | Supported boundary |
|---|---|
| Model Context Protocol | Version `2025-11-25` Streamable HTTP under `/anonymous-simulation/mcp`. |
| JSON Schema | Draft 2020-12 strict tool, resource, camera, product, and lease shapes generated by the selected SDK. |
| `veoveo.io/live-view/v2` | Stable authoritative camera/product identity and ephemeral actor-and-browser viewer leases. |
| `veoveo.io/gateway-server-fragment/v1` | Extension-owned server and App contribution. |
| `veoveo.io/extension-release/v1` | Immutable independently published release inventory. |

## Ownership

The extension owns one camera descriptor, one stable encoded-product descriptor,
viewer leases, token rotation, signaling authorization, resources, and its MCP App.
The installation owns gateway exposure, public network coordinates, trust, image
digests, and deployment policy.

The fixture's product is synthetic. It declares the same strict identity and capacity
shape that a real simulator implements, but it does not claim hardware rendering,
NVENC execution, advancing video, or browser playback. First-party UAV acceptance and
each external simulator's own GPU qualification provide that evidence.

## MCP Surface

The server exposes `list_live_cameras`, `open_live_view`, `renew_live_view`, and
`close_live_view`. Resources remain under `anonymous-simulation://` and publish
redacted camera, product, fixture, and viewer state. Open and renew return one bounded
token; only its SHA-256 hash remains in memory.

Every lease binds the gateway actor, output owner, browser instance, camera, and stable
product. Concurrent users share the product identity while receiving distinct lease IDs
and tokens. Exact deadline tasks close expired leases. There is no persistent renderer
state or retry loop.

## Deployment

The Helm workload runs as UID 10001 with a read-only root filesystem and no service
account token. Network policy admits gateway traffic, DNS, and its declared signaling
and media ports. The chart has no separate renderer, pose endpoint, scene cache, or
second workload.

The CPU-sized fixture resources are intentional because this chart exercises packaging
and governance only. They cannot satisfy the repository's hardware visual gate.
