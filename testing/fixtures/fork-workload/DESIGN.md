# Fork Workload Fixture Design

This fixture proves that an in-repository Python MCP server can expose a
simulator-hosted live-view contract using the local SDK.
It is a protocol fixture rather than visual or GPU evidence.

## Standards And Protocols

| Standard or protocol | Supported boundary |
|---|---|
| Model Context Protocol | Version `2026-07-28` stateless Streamable HTTP under `/anonymous-simulation/mcp`, with mandatory per-request metadata and `server/discover`. |
| JSON Schema | Draft 2020-12 strict tool, resource, camera, product, and authorization shapes generated by the selected SDK. |
| `veoveo.io/live-view/v4` | Typed camera regions in stable authoritative products, independent actor-and-browser authorization, and shared Annex B H.264 WebSocket fanout. |

## Ownership

The workload owns one camera descriptor, one continuous stream product, viewer
authorization, token rotation, resources, and its MCP App.
The installation owns gateway exposure, public network coordinates, trust, image
digests, and deployment policy.

The fixture's product is synthetic. It declares the same strict identity and region
shape that a real simulator implements, but it does not claim hardware rendering,
NVENC execution, advancing video, or browser playback. First-party UAV acceptance and
each simulator's own GPU qualification provide that evidence.

## MCP Surface

The server exposes `list_live_cameras`, `open_live_view`, `renew_live_view`, and
`close_live_view`. Resources remain under `anonymous-simulation://` and publish
redacted camera, product, fixture, and viewer state. Open and renew return one bounded
token; only its SHA-256 hash remains in memory.

Every authorization binds the gateway actor, output owner, browser instance, and camera.
Concurrent users receive distinct authorization IDs and tokens while retaining the same
stream-product identity. Exact deadline tasks revoke expired authorizations. There is no
viewer quota, persistent fixture renderer state, or retry loop.

## Deployment

The Helm workload runs as UID 10001 with a read-only root filesystem and no service
account token. Network policy admits gateway traffic, DNS, and its declared shared stream
endpoint. The chart has no separate renderer, pose endpoint, scene cache, or
second workload.

The CPU-sized fixture resources are intentional because this chart exercises packaging
and governance only. They cannot satisfy the repository's hardware visual gate.
